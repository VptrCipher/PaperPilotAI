What it does

One paper in. Four outputs, and a report.

Upload a text-based PDF, or open the bundled FAIR sample. Everything below is generated from that one paper.

01 · Summary

A plain-language summary

Ask for a simple-language summary and get eight research sections, from the overview and problem to findings, limitations and conclusion. Each section lists the PDF pages it drew on.

02 · Concepts

Concepts, kept honest

The methodology and its important concepts, explained in plain terms. General background is labelled separately from what the paper itself says.

03 · Slides

Slides you can edit

Five to ten slides with short bullets and a source-page footer, exported as a widescreen PowerPoint file you can edit like any other deck.

04 · Viva

Viva practice that answers back

Practice questions with suggested answers, a difficulty label and citations. Then type your own answer and the local model gives advisory scores for correctness, depth and clarity, one next step and the pages that support it.

05 · Report

A report you can keep

Download a Markdown report of the session: every request and result with its page citations, your viva attempts and feedback, and the real activity trace.

Request

Routed toSlide-Generator agent

Returns five to ten slides checked against a schema, with a PowerPoint download.

Request

“Generate ten viva questions with easy answers.”

Routed toViva agent

Returns questions with answers, difficulty and citations, with answers hidden until you reveal them.

Request

“Compare it with the other approach.”

Routed toA clarifying question, no search

A comparison with nothing yet discussed gets a question back, not a guess.

How it works

How a request travels.

Every step runs on your machine. The route a request takes is shown in the app's Agent Activity panel.

  1. 1

    Read the PDF

    PyMuPDF extracts the text page by page, in order. Recognized headings label the text around them.

  2. 2

    Split into overlapping chunks

    LangChain cuts each page into chunks of up to about 1,000 characters with up to 150 characters of overlap, so a passage that crosses a boundary keeps its meaning. Every chunk keeps its page.

  3. 3

    Embed and store

    A MiniLM sentence-transformer turns each chunk into a vector, and ChromaDB keeps the vectors, text and page numbers together in a collection made for this paper. Prefer no model at all? An offline lexical index does the same job with shared words.

  4. 4

    Route the request

    A local model reads the request and picks an agent: summary, concepts, slides, viva, a clarifying question or app help.

  5. 5

    Decide whether to search

    The model chooses to retrieve new excerpts, reuse the ones it has, or ask you to clarify. Retrieval fuses meaning with exact wording, and a thin result triggers one more targeted search.

  6. 6

    Generate and check

    The chosen agent writes from the excerpts. Pydantic validates the structured result, and the page references are checked against the evidence.

  7. 7

    Show the evidence

    The result appears with the PDF pages and excerpts it used, and the routing and retrieval actions appear in Agent Activity. Slides export to PowerPoint.

On your machine

Runs on your machine.

PaperPilot talks to a local Ollama model on your own computer. After setup, reading, embedding, search, generation and export all happen locally.

  • 01

    A local model

    Ollama serves the model on a loopback address. The default is Qwen2.5 3B, about 1.9 GB, and you can choose another installed model in the sidebar.

  • 02

    Two ways to search

    Semantic search uses the pinned MiniLM weights and is combined with exact-word matching. The offline lexical index needs no download and matches shared words, so it is weaker on paraphrases.

  • 03

    A local index

    The paper's vectors live in an in-memory ChromaDB collection that is removed when you replace or reset the paper.

  • 04

    No automatic downloads

    The app never downloads a model by itself. Setup needs the network once for packages and model weights; processing runs locally afterward.
